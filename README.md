# XYZPDF

Windows 桌面 PDF 阅读器。工具链、目录结构、构建脚本和测试方式与同一作者的
[XYZip](H:/test/XYZip) 一致。

**整体方案在 [docs/PLAN.md](docs/PLAN.md)，动手前请先读完。** 实现约定在
[CLAUDE.md](CLAUDE.md)。

## 现在到哪一步了

按方案 [§4 里程碑](docs/PLAN.md) 的划分，**M0（骨架）已完成**：

- 双击 `.pdf` / `xyzpdf.exe <file>` 能打开，窗口标题是文件名，关掉不崩
- **单实例网关**：第二次启动把文件通过命名管道交给第一个实例，开成新标签页
- `MainWindow : DocumentTab = 1 : N` 的类划分已经成立，标签栏在只有一个标签时自动隐藏
- 视图是自己写的 `PageView`（不用 `QPdfView`）：连续滚动、页面间距、占位页、
  Ctrl+滚轮**以光标为锚**的缩放、适应宽度/适应整页、旋转、键盘翻页
- 渲染走 `PageRenderer`（Qt PDF 的多线程模式）不上 UI 线程，回来的图按**代次令牌**
  判断是否还该上屏；渲染结果按**像素字节数**做 LRU 缓存（默认 256 MB，可配）
- **内存有上限**：视图只留"看得见的页 + 预取额度内的邻居"，且预取按**字节**给额，
  不按屏数；比视口大得多的页（800% 一张 A4 是 288 MB）只渲染屏幕上那一条
  （`setScaledClipRect`），实测 2500×1400 的一条是 12.7 MB
- **拖放打开**：从资源管理器把 PDF 拖进窗口任意位置即可打开（窗口是拖放目标，标签栏、
  页面、空状态上都行）；已经打开的文件会把它的标签提到前面而不是开第二个；
  拖进来的动作一律按「复制」处理——只允许移动的拖放会被直接拒绝，绝不接受移动，
  免得把用户的原文件搬走
- **三种鼠标工具**（工具栏最左边三个按钮，或 查看 菜单 / `Ctrl+Shift+1/2/3`），
  一次只有一个生效，指针形状说明当前是哪个：
  - **只查看**：指针是手形，按住拖动**平移页面**，不碰页面上的任何内容
  - **选择**：选文字（拖选、双击选词、Shift 扩展、Ctrl+A 全选、Ctrl+C 复制），
    选中处有蓝色底色，跨页选中按页拆成多段并在复制时用换行分隔；
    指针移到文字行上变成 I 形（由 `Document::hasTextAt()` 判定，页边距和纯图片页不算）
  - **识别**：指针是十字，拖出矩形框后识别框内**像素**里的文字（扫描件、
    图片里的字都能读），结果弹在独立窗口中可一键复制，指针是十字
  - 之所以分成三种：在这之前"拖动"的含义由指针位置隐式决定（I 形=选字、箭头=拉框），
    于是扫描件里选文字变成了拉框，文字上想拉框只能靠按 Alt——两种功能互相抢同一个手势。
    识别用 Windows 自带的离线 OCR（`src/ocr/ocrengine.cpp`），不联网、不装额外组件，
    识别语言跟随系统语言包；没有语言包的机器会在窗口里如实说明
- **工具栏**：默认**一排**（密实排布，放不下的整项藏起来），最右侧只有一个小的 `…`；
  **点击 `…` 展开成多排、显示全部内容，再次点击才收回**——鼠标移开、在工具栏里打字、
  窗口重排都不会让它自己缩回去（Qt 原生 `》` 的展开态是瞬时的：鼠标离开或任何一次重新布局
  就没了，且没有公开 API 能留住它，所以这个展开状态由 `src/ui/wrappingtoolbararea.*` 自己持有，
  只有点击能改变它；被压窄的工具栏自己那个 `》` 会被隐去，避免"两个按钮一个意思"）。
  窗口最小宽度按最宽的那一组实测设定，保证"展开就一定看得全"这条承诺成立
- **全文搜索**：两个入口，**一处状态**——工具栏最右的搜索框，和 `Ctrl+F` 在标签内打开的
  查找栏；在任一处输入的查找词，另一处会同步显示，命中与计数也是同一份
  - 输入即搜，跨页统计，并显示"**第 N / M 个**"：工具栏搜索框旁的计数、查找栏里的计数同时更新
  - `Enter`/下一个、`Shift+Enter`/上一个、`F3`、`Shift+F3`；查找栏可勾选区分大小写
    （工具栏框沿用它的设置），`Esc` 清除搜索
  - 命中处以琥珀色高亮（当前命中加重），跳转把命中放在窗口上三分之一处——命中上方留着
    上下文才好读
  - 扫描在 UI 线程之外进行（`text()` 是每页一次 PDFium 调用，与渲染共用同一把全局锁），
    换查找词、关栏、换文档都会取消并丢弃旧结果
  - 搜的是 PDF 的**文字层**：扫描件（本来就没有文字层）搜不到，那类文件请用"识别"工具框选
- **导出为 Word**：`文件 → 导出为 Word…` 把整份 PDF 导出为 `.docx`。
  **有文字层的页出文字，没有文字层的页出图片**——一份"文字封面 + 扫描正文"的文件
  会得到同样的结构：
  - 文字页：先**把同一行上的多个文字框合并成一行**（一行文字可能是被分成几块画的：两端对齐的
    排版、带上标的一行、逐块定位的一行；一个框当成一行会把一句话拆成"推荐"/"使用"/"较高"这样的
    一段一个词），再按页面位置归并成段落。换段的判据按可靠性排序：
    ① 行间距明显大于**这页自身的行距**（取中位数——拿"行高"当基准是错的：某份报告的
    10pt 字配 31pt 行距，41 行就被拆成 41 段）；② 行宽不到栏宽一半（必然是本段最后一行，
    或一条清单项）；③ 行尾是句末标点且明显没到右边界；④ 缩进变化。中英混排时中文之间不插空格
  - 图片页（扫描件、整页图片、绘图页）：把该页按 **150 dpi 渲染成 JPEG**（先合成到白底——
    PDF 页面本身没有背景，带透明度的图放进 JPEG 会变成黑底），插进文档并保持页面原貌与
    长宽比；单页像素上限 800 万，超过就降低缩放而不是放弃这一页
  - 页与页之间是**分页符**；纸张尺寸取自 PDF 第一页（页边距 0.5 英寸），页面图片才不会被
    读者那边默认的 Letter 纸张切掉；结果消息如实说明"几页、几段、其中几页按图片还原"
  - 转换在工作线程上跑（读文本与渲染共用同一把全局锁，放在界面线程会让窗口停止重绘），
    切换文档会**取消**它并等它停下——和在读的文档被换掉是崩溃而不是错答案
  - **不导出字体与排版**：字号、粗斜体、表格、以及**文字页内部的图片**都没有——Qt PDF
    不提供字体信息，凭空编造会让转换看起来比它实际更好；图片页里的字也不能直接编辑，
    要可编辑的文字请先用「识别」工具
  - 文件是自己写的标准 OOXML（`src/export/`：ZIP 写入器 + `word/document.xml`），
    零第三方依赖；条目按格式规定不压缩存放，Word / WPS / LibreOffice 都能打开；
    `python tools/check_docx.py 文件.docx` 可以用**完全独立**的实现（zipfile / ElementTree）
    校验产物：每个 CRC、每个部件的合法性、以及"drawing 引用的关系指向的媒体部件确实存在"
  - 文字层里 XML **根本无法承载**的字符会被丢掉而不是写出去：控制字符、`#xFFFE`/`#xFFFF`
    这两个非字符、以及落单的代理项——PDF 的文字层什么都可能有，而带上它们的文件不是
    "有个怪字符"，是**Word 打不开**（真实手册里就有，换行被编码成 `#xFFFE`）；
    成对的代理项（emoji、生僻字）会原样保留
- 主题（浅色/深色）、语言、最近文件、设置、关于、第三方许可
- 中文/英文两套界面（英文目录已完整翻译）

还没做，且都在方案里排了队的：侧栏（缩略图/书签）、搜索结果列表、双页/书籍模式、
打印、导出成其他格式（PDF 图片/纯文本）、**带排版的** Word 导出（需要真正的字体信息，
要等 v2 的 PDFium 后端）、导出时的选项（页码范围、是否把扫描页换成图片、图片分辨率）、
标签页的完整交互（拖拽重排/拖出成新窗口）、资源管理器右键菜单与预览窗格、
MSIX 打包。`packaging/` 目前只有两个清单占位，打包脚本排在 M4。

「选择」工具目前只选文字；把页面里的**图片**当对象选中（框选后复制图片到剪贴板、
或导出图片）还没做——如果需要，说一声，做法和识别工具共用同一套裁剪渲染。

## 构建

```powershell
# 一次配置 + 构建 + 跑全部测试
python tools\build_all_tests.py

# 只要构建
python tools\build_all_tests.py --build-only
```

脚本自己会去找 cmake、vcvars64.bat 和这台机器上的 Qt（也可以用 `--qt` 指定）。
生成器固定为 Ninja，构建目录默认 `build-local-release`。

构建后会**自动 `windeployqt`**，把 Qt 的 DLL 和插件部署到 exe 旁边，所以
`build-local-release\xyzpdf.exe` 可以直接双击运行，不需要把 Qt 的 bin 加进 PATH。
测试程序不带这份部署（它们在 `build-local-release\tests\`），由脚本运行时给它们
加上 Qt 的 bin —— 这也是为什么测试要经由脚本跑，而不是直接双击 exe。

**不要删构建树里的 `CMakeCache.txt`**：本项目不带 CMakePresets，Qt 的位置只存在于
缓存里。要换 Qt，重新配置一个新目录，或删掉整个构建目录后让脚本重新找。

## 测试

`tests/*_smoke.cpp`，每个模块一个，用 `tools/build_all_tests.py` 一把梭
（**配置 + 构建 + 运行**；只跑不构建会拿陈旧 exe 骗自己）。

工作目录必须是源码树，因为固件按相对路径打开。测试用到的 PDF 由
`python tools/make_fixtures.py` 生成，已经提交在 `tests/fixtures/`。

现有的 smoke：`version` `commandline` `instancegateway` `i18n` `document`
`outline` `textlayer` `render` `cache` `layout` `zoom` `documenttab`
`shellintegration`。

其中 `documenttab` 是把 `PageView` 与 `DocumentTab` 接起来的那一个：缩放、旋转之后
页面是否**真的上屏**，只能在这个层次上验——各部分的单元测试都对，照样可能因为两个
信号的先后顺序而永远只有灰底。

## 目录

```
xyzpdf/
  CMakeLists.txt      单一构建脚本：版本、选项、目标、翻译、测试开关都在这里
  main.cpp            语言、主题、单实例、命令行
  mainwindow.*        窗口级：菜单、工具栏、标签容器、最近文件、设置
  documenttab.*       文档级：一个标签 = Document + 渲染 + PageView + 缓存
  src/core/           设置、临时文件、窗口级对话框、语言表、最近文件、关于、许可
  src/document/       只读文档接口与 Qt PDF 后端、页面度量、书签树
  src/render/         代次令牌、异步渲染器、按字节计上限的缓存
  src/view/           自绘页面视图、页面排版、缩放控制器
  src/theme/  src/ui/  src/settings/  src/cli/  src/windows/
  packaging/          MSIX 清单（打包脚本在 M4）
  tools/              build_all_tests.py、add_language.py、make_fixtures.py、makeappicon.py
  tools/pdfprobe.cpp  量一个文档：每页多少像素、渲染多久、缓存能装几页
  tests/              *_smoke.cpp 与 fixtures/
  Resources/          图标、许可证、翻译
```

## 量一个文档

"这个文件为什么慢"没法从文档描述里回答，只能量：

```powershell
python tools\build_all_tests.py --build-only   # 会一并构建探针（XYZPDF_BUILD_PDFPROBE）
build-local-release\xyzpdf_pdfprobe.exe "D:\某文档.pdf" 12 2500
```

它打印页数、页尺寸、按"适应宽度"算出来的缩放、抽样页的像素尺寸/字节数/渲染耗时，
以及 400% 下整页与"屏幕上那一条"的字节数对比。任何名字里带 `probe` 的目标都不会被
测试脚本当成测试跑。
