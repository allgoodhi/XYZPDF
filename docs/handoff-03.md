## F8. 就地保存与标准的保存/另存为　分支：`save-in-place`（第三阶段）

**规矩**：`AGENTS.md` 已改成"除了「保存」这一条路，永不写用户的 PDF 文件"。这一支就是那一条路，写法必须如下，
任何别的代码路径都不许写用户的文件。

**要做**
1. 菜单：**保存(&S)** Ctrl+S（写回打开的那个文件）、**另存为(&A)…** Ctrl+Shift+S（标准行为：写到新路径，
   **标签切到新文件**，原文件不动）。现在的「保存修改为…」由这两项取代；七条编辑工具提示里"按保存修改为才写成一个新文件；
   正在读的这份不动"全部改写成真话。目录跟着删、填（英文助记符写在词内）。
2. **就地保存的写法**（顺序不能换）：
   a. qpdf 写到**同一目录**下的临时文件（同卷才能原子替换；名字带随机后缀，隐藏属性）；
   b. 用 qpdf 重新打开临时文件验证（能开、页数等于预期）；验证不过 → 删临时文件、原文件不动、说清楚；
   c. 等所有还在读文档的工作结束（`drainRenders()` 那一族），释放我们对原文件的句柄；
   d. `ReplaceFileW(原文件, 临时文件, nullptr, REPLACEFILE_WRITE_THROUGH, …)` —— 保留原文件的 ACL、属性与创建时间；
   e. 重新打开，回到原来的页码、缩放与侧栏状态；编辑状态清空；
   f. 替换失败（别的程序独占着、只读、权限）→ 原文件**逐字节不变**、临时文件删掉、我们重新打开原文件、
      提示里给「另存为」这条路。
3. **自己的保存不许触发**"文件在外面被改了"的提示条（B 的 `QFileSystemWatcher`）：保存期间暂停监视或认出自己的写入，
   测试钉住"保存后 2 秒内没有提示条"，同时钉住"保存后别人再改一次照样提示"。
4. 加密的文档：保存后的加密状态等于待保存操作说的那样（没有加密操作 → 原样保留口令与权限）。
5. 标题栏/标签：有未保存修改时带 `*`；关闭标签、退出程序时有未保存修改 → 保存 / 不保存 / 取消 三选一
   （现在若已有类似的框，改成这三个按钮的标准形状）；`ForegroundJob` 期间的规矩不变。
6. 只读文件、`WindowsApps` 里的文件、网络路径断开：各有一句说清楚的话，并给「另存为」。
7. **测试**（全在临时目录的副本上，绝不碰 fixtures 原件）：就地保存后字节变了且能打开、页数对、视图回到原页；
   替换失败那条用另一个句柄不带共享地占住文件 → 原文件 sha256 不变、临时文件不残留；另存为后标签路径是新文件、
   原文件 sha256 不变；监视器两条（见 3）。每条配控制跑。
8. F7 的句柄改造（`FILE_SHARE_DELETE`）和这一支是两头：F8 自己要先释放句柄再替换，所以**不依赖** F7 也能过；
   合并后主会话会再验一次两者合在一起的那条路。

测试锚点：`documenttab_smoke` 在 `    // ---- 加密 / 去掉口令: the box and the editor refuse the same requests ----` 之前；
`mainwindow_smoke` 在 `    // ---- a second document joins the first ----` 之前。

## F10. 识别线程的那次 0xC0000005　分支：`ocr-worker-crash`（第三阶段）

**背景**：F4 用测试进程内的崩溃转储拿到了 §103 那次崩溃的形状（`test-debts` 分支的提交说明全文，§112 摘要）：
- 门禁那颗 exe：**识别任务的工作线程**里一次虚调用 `call [rax+0x50]`，目标地址**不在任何已映射的镜像里**；
- 带调试信息那颗：同一处变成 `QUnhandledException` 被带回 UI 线程，在 `startRecognition` 的 `finished` 里重抛，没人接。
主会话合并时补了半截（`ocrengine.cpp` 的 `recognizeWorker` 加了 `catch (...)`，把第二种形状变成一句"识别时出错了。"），
**第一种没解释**。"地址不在任何镜像里"最像的是**某颗 DLL 已经卸载了还在被调用** —— 例如进程或测试块结束时识别还在跑。

**要做**
1. 用 F4 装好的崩溃转储（`XYZPDF_TEST_CRASH_DUMP`）复现，查清那次虚调用的对象是谁、那颗 DLL 什么时候被卸载。
   要符号就在**临时的、不进版本库的**构建树里加 `/Zi /DEBUG`（F2 之后构建是可重现的，记下这颗树与门禁那颗只差这一处）。
2. 按查到的原因修**产品**：比如退出/关标签时取消并等待识别任务、`winrtPool()` 那个函数内静态 `QThreadPool` 的析构次序、
   apartment 的生命周期 —— 以量到的为准，不要先猜后改。
3. 一条能红的测试：在修好的代码上复现那条路（识别跑着的时候关标签/结束），控制是撤掉修复必须崩或红。
4. 产品里真实的触发面要写清楚：用户在什么操作下会遇到（比如"识别还没回来就关掉程序"）。

测试锚点：`documenttab_smoke` 在 `    // ---- the region snapshot ----` 之前（截图与识别那一带；不要和 F8 用同一行 ——
两个分支往同一处插入，git 合并必冲突）；不需要就不改 `mainwindow_smoke`。
